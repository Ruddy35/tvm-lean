# Покрытие C++ при сверке (фаза 2)

Цель фазы 2 — измеримое «один в один»: каждая ветвь C++-кода VM, исполняемая при обработке
транзакции, должна быть пройдена хотя бы одним тестом, сверяющим модель с C++.

## Как измеряется

- `scripts/build-cpp-coverage.sh` — эталонный `fift` (`ton` @ `3d478cb`) собирается с `--coverage -O0`
  в `~/ws/ton-build-cov`; инструменты сборки ставятся локально, без root.
- Сборка с покрытием ведёт себя как эталонный бинарник: полный оракул через неё — 25 777 / 25 777
  на версиях 13 и 16, unit-тесты 5967 / 5967.
- Прогоны сверки с `TON_FIFT_BIN` на эту сборку накапливают счётчики; `scripts/cpp-coverage-report.sh`
  строит отчёт по `crypto/vm`.

## Находки фазы 2

**182 набора тестов из 918 — пустые заглушки:** ни unit-тестов, ни случаев оракула, ни fuzz. Эти
инструкции с C++ не сравнивались вовсе; их касались только дифференциальные прогоны контракта
TON Storage, и только в той мере, в какой он их использует.

Причина пустоты кортежей и окружения — ограничение оракула: в начальный стек C++ нельзя было
передать непустой кортеж. Добавлен токен `TUP:<n>` (вложенные кортежи — рекурсивно).

**Категория fuzz не входила в полную сверку.** Её 405 676 случаев на версию прогнаны впервые (обе
версии — одинаково), 9 отказов:

| Набор | Расхождение | Природа |
|---|---|---|
| `DICTUSET` (4) | газ: модель 1686, C++ 686 | газ кончается внутри инструкции: C++ бросает на первом превышении (`consume_gas` при создании ячейки), модель списывает операцию целиком |
| `PFXDICTGETEXEC` (4) | газ: модель 176, C++ 276 | на испорченном словаре C++ загружает ещё одну ячейку до ошибки `cell_und` |
| `LSHIFTADDDIVMODR` (1) | — | дефект генератора: слишком большая ячейка для BOC |

Это открытые ошибки модели (газ в словарях). Fuzz теперь входит в `scripts/verify-all.sh`.
