# План

Фазы идут по порядку. Фаза считается закрытой только по критерию готовности.

## Фаза 0. Чистая база — **закрыта**

Модель отделена от работы по конкретным контрактам, каждое изменение — отдельный коммит с
обоснованием. Сверка на ветке: unit 5967/5967, оракул 25 760/25 760 (v13 и v16), дифференциальные
прогоны 35 889/35 889. Найдена и исправлена ошибка исходной модели (`QPOW2`).

## Фаза 1. Аудит по исходникам C++

- Исходники `ton` @ `3d478cb`; извлечь полную таблицу опкодов из регистраций `OpcodeInstr`
  (`crypto/vm/*.cpp`) и сопоставить с декодером модели (`Cp0`) и обработчиками.
- Все проверки `get_global_version()` в C++ — сопоставить с моделью.
- Недостающие инструкции: известны `EXTCALL`, `XCHG_IJ`, `SETCP_SHORT`; полный список даст аудит.

**Готово, когда:** каждый опкод C++ сопоставлен с моделью; каждое ветвление по версии в C++
либо реализовано, либо внесено в план с номером версии.

## Фаза 2. Измеримое «один в один»

- Собрать C++ TVM с покрытием (`gcov`), прогнать через неё оракул и дифференциальные тесты.
- Для непокрытых ветвей C++ писать целевые тесты, пока покрытие ветвей VM не станет полным.
- Исчерпывающая сверка там, где пространство конечное (например, декодер на всём пространстве опкодов).

**Готово, когда:** отчёт о покрытии ветвей `crypto/vm` и все случаи совпадают.

## Фаза 3. Все глобальные версии

Модель сейчас начинает с версии 13. Добавить поведение всех версий, поддерживаемых эталонным релизом.

**Готово, когда:** оракул проходит на каждой версии.

## Фаза 4. Криптография и хэши на Lean

Убрать внешние функции `Host`: blake2b, keccak-256/512, ed25519, secp256k1 (ecrecover, tweak add),
P-256, ristretto255, BLS12-381 (G1/G2, спаривание, hash-to-curve).

**Готово, когда:** `Host` пуст; оракул и стандартные тестовые векторы каждого примитива сходятся.

## Фаза 5. Фазы транзакции

По `crypto/block/transaction.cpp`: хранение, кредит, исполнение, действия (режимы отправки,
резервы, `SETCODE`, библиотеки), bounce; параметры конфигурации.

**Готово, когда:** дифференциальная сверка целых транзакций с эмулятором транзакций C++.

## Фаза 6. Доказательные обязательства модели

Доказать оставшиеся равенства рефакторингов исходным определениям (см. `docs/model-changes.md`);
доказать общие свойства модели (границы ячеек, детерминированность и т. п.).

## Фаза 7. Индукция и инварианты

Общая теорема индукции по транзакциям; символьное исполнение байткода с доказанной корректностью;
генерация условий проверки инварианта и их закрытие решателями. Приёмочный тест — доказательства
по контракту TON Storage, которые раньше делались вручную (архив вне репозитория).
