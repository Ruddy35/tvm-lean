## 2. Исчерпывающее сравнение декодеров — выполнено

`tools/audit/decoder/run.sh` (`Apps/AuditDecoder.lean` и `tools/audit/decoder/cpp.fif`): каждое
24-битное значение с двумя хвостами (480 нулей или единиц) и четырьмя пустыми ссылками декодируется
моделью и таблицей диспетчеризации C++ (`(vmoplen)`, `(vmopdump)`). Дополнительно для каждого
16-битного префикса модель пересобирает декодированную инструкцию (`encodeCp0`), а C++ печатает и
исходный опкод, и пересборку: совпадение означает ту же инструкцию с теми же аргументами.

| Показатель | До исправления | После |
|---|---|---|
| Значений (на каждый хвост) | 16 777 216 | 16 777 216 |
| Допустимых: C++ / модель | 15 313 543 / 15 305 843 | 15 313 543 / 15 313 543 |
| Расхождений длины или допустимости | 8724 | **0** |
| Пересборка: проверено | 59 794 | 59 826 |
| Пересборка: инструкция по C++ различается | 7 | 7 |
| Пересборка: кодировщик модели не умеет | 6371 | 6371 → 5920 → **0** (`encodeCp0Code`) |

Исправлено (коммит «model: decoder mirrors the C++ dispatch table exactly»):

- семейства деления (`A90…A9D`, тихие `B7A9x`): режим округления 3 декодируется, как в C++, и
  выполняется как `inv_opcode` после списания газа инструкции;
- `F2F6` недопустим (`mkfixedrange(0xf2f0, 0xf2f6)`);
- `EXTCALL` удалён — такой инструкции в эталоне нет.

Остаётся:

- 7 расхождений пересборки — длинные формы с нулевым или малым аргументом (`XCHG s0` = `11 00`,
  `PUSH s0`, `POP s0`, `GETPARAMLONG 0` и т. п.): модель декодирует их правильно, а при пересборке
  выбирает короткую каноническую форму. Это свойство кодировщика, не декодера.
- Пересборка теперь покрывает всё: кодировщик `encodeCp0Code` выдаёт биты, встроенные данные и
  ссылки. Для всех 59 826 декодированных инструкций (на каждый хвост) запись C++ пересборки совпадает
  с исходной, кроме 7 канонических форм выше. Значит, для каждого 16-битного префикса модель
  декодирует ту же инструкцию с теми же аргументами, встроенными данными и ссылками, что и C++.
- Тождество на всех 2²⁴ значениях (`tools/audit/decoder/identity_all.sh`): для каждого из
  15 313 543 значений, которые C++ декодирует (на каждый хвост), C++ печатает пересборку модели так же,
  как исходный код, кроме тех же 7 групп длинных форм (1539 значений: `XCHG s0`/`s1`, `PUSH s0`/`s1`,
  `POP s0`/`s1` с любым третьим байтом, `GETPARAMLONG 0..2`). В них модель декодирует инструкцию с
  тем же поведением (`XCHG s0` — пустая операция, `PUSH s0` = `DUP`, …) и той же длиной, то есть
  тем же газом. Итог: декодер модели читает ту же инструкцию с теми же аргументами, что и C++, на
  всём пространстве опкодов.
- Запись инструкций различается в 28 158 случаях из 59 826: модель печатает не в формате C++. На
  семантику не влияет; проверка тождества идёт через пересборку.
- Газ и поведение `invalidArgs` подтверждены оракулом: 17 случаев в наборе `DIV`, все 13 семейств
  и обрезанный опкод, версии 13 и 16.

| Группа | Проверок | Статус |

Сверка 33 проверок уровня VM с порогом ≥ 13:

- `exec_shrmod`, `exec_lshift/rshift_tinyint8` (v14), `exec_mulshrmod`, `exec_shldivmod`,
  `exec_lshift`, `exec_rshift`, `exec_pow2`, `exec_and`, `exec_or` (v13) — арифметика модели;
  `QPOW2` исправлен по этой описи.
- `silent_if_set` (v14) в восьми функциях установки регистров управления — `defineCtr`.
- `exec_ed25519_check_signature`, `exec_ecrecover`, `exec_ristretto255_mul`,
  `exec_store_opt_std_address`, `exec_send_message` (v14) — исправлены ранее сверкой.
- `exec_ristretto255_mul_base` (v14, две проверки): ранний выход при `n % l = 0` есть в модели;
  вторая проверка (до v14 ошибка только если результат остался `0xFF…`) воспроизведена хост-функцией
  `c/tvmlean_crypto_ext.c`, а при v14 разница ненаблюдаема — умножение не удаётся только при
  `n ≡ 0 (mod l)`, который обработан ранним выходом.
